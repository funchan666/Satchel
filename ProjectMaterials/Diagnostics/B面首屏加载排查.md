# Satchel B 面首屏加载排查

## 现象与证据

- 2026-11-04 10:53，iPhone 18 Pro 模拟器启动：游客登录约 2.09 秒，发布配置约 0.60 秒；H5 初次导航从开始到完成约 18.33 秒。开屏广告关闭后，App 继续等待约 13.84 秒才显示页面。
- App 在开屏广告期间已经启动 B 面 WebView；初次主页面提交后，首屏可见内容检查没有先于 `didFinish` 报告就绪。本次日志不能单独确定是哪一个网页资源耗时。
- 同日对先前联调 H5 地址的无参数只读请求返回 HTTP 200。返回页面中存在 `/@vite/client`、`/src/main.js`、`/node_modules/.vite/` 等 Vite 开发服务资源；HTML 的 head 中同步引用 Telegram 脚本和 Adexium 脚本。这次独立请求并不等同于模拟器完整带参数加载，不能仅凭它认定任一资源就是根因。

## 请 H5 团队核查

1. 在同一模拟器／网络条件下抓取包含首次访问和缓存关闭两种情况的 Network 瀑布图，记录 HTML、第三方脚本、首屏 JS/CSS、接口及 DOMContentLoaded／首屏渲染时刻；不要在截图或日志中暴露设备号、token 或完整带参数地址。
2. 测试环境若允许，将当前 Vite 开发服务改为构建后的静态资源，并配置正确缓存及 SPA 路由回退；对比上线前后首屏耗时。
3. 检查第三方脚本是否阻塞 HTML 解析；在不改变广告功能和初始化先后关系的前提下，考虑异步加载并处理加载失败。不要简单删除广告脚本。
4. 保护已有入口参数 `deviceCode`、`appId`、游客身份、WebSocket 支付／广告请求和结果回传；确认首屏数据加载不受构建／缓存改动影响。

当前 App 端已有可见内容就绪判断和超时回退；这里提出的是待 H5 团队核对的性能方向，不代表已实施或验证完成。
